- 当前没有可调用的 Unreal MCP 工具。使用已有 UE PythonScript commandlet 在独立资产工程导入，没有连接或修改用户正在运行的编辑器。
- 按用户最新“实际需要保留”的反馈，保留 PythonScriptPlugin 及远程执行设置：启用、绑定 `127.0.0.1`、Multicast TTL=0。先前要求移除时生成的独立副本保留为历史；当前部署与源配置一致。

STL 在 SDF 中按米使用，转换为 UE 厘米并反射 Y。实际 UE FBX 导入还会强制反射一次 Y，因此第一版导入存在 0.276905775 cm 机体边界错误。安装目录内的 `FbxUtilsImport.cpp` 证实此行为；专用导入适配抵消多余反射后，三网格原生边界通过预先固定的 0.002 cm 导入诊断。该值不是动力学等价预算。

## 最小显示修复与构建

按 diagnosing-bugs 的红→绿反馈流程，先在不启动飞控/物理、不注入状态的原生 UE 场景重现黑/暗帧。固定中央 ROI `(0.15,0.25,0.85,0.92)`，平均亮度至少45、暗像素比例至多0.25、过曝比例至多0.15。此诊断只针对原先的黑/暗画面，不代替机型、相机或传感器标定。

保留 `validation/visual-readability-20260906/` 下的基线、曝光关闭、太阳角度、相机曝光切换、太阳可移动性探针。只改变太阳 Stationary→Movable 的探针通过；最终修复保留原太阳颜色、方向和强度，不增加发光材质或处理截图亮度。源码已清除临时 DEBUG 和诊断参数。

正式显示先发 `WKSIM_STARTING`，在待编译资产连续至少三帧为零、初始 RHI 渲染命令栅栏完成后才发 `WKSIM_READY`。轮询而非阻塞，不连接物理时间。截图也在此后开始。亮度回归 `regression-green-1` 和 `original-loop-green` 分别得到3、5个原生可读帧；P450 最终 `p450-balanced-three-frame` 得到5帧，无源码漂移。

旧4秒轻量测试只产生2帧，旧工具把“最多三帧”误算为足够；保留其原始结果，新增回归检查并改为原生至少3帧，再按8秒重跑。离线单图测量仍可以选择一张，不能冒充三帧验收。

本机 RTX5060 8 GB 与用户已有编辑器共存时，原显示质量截图出现显存告警。当前独立查看器使用 `desktop-balanced`：30 FPS，阴影/GI/反射/纹理质量1；人工检查的后续原始 PNG 不再有该告警。未隐藏告警、未关闭用户编辑器，也不承诺所有设备与场景都无显存压力。场景细节/阴影质量仍是工作视图水平。
