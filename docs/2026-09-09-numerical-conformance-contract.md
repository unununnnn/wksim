# #23 固定参考输出保留合同 v1

2026-09-09。已生成[机器合同](../Simulator/wksim_core/numerical-conformance-v1.json)与三份501行CSV，主代理已在这些对照工况执行前复核并设为 **frozen**。提案原字节保留在 `validation/numerical-contract-20260909/proposed-contract.json`；执行器必须在任何对照开始前另存冻结合同原字节与SHA256。冻结阶段未执行这些载具对照，不需新增用户审批轮次。参考端使用无损little-endian binary64或MAT double数据，不能因JSON十进制窄化形成假差异。

本次工程用途明确为“移植保留固定参考模型在声明工况中的原生输出值”。它采用一个保守且可能失败的充分判据：**两侧每个有限binary64数值完全相等，绝对预算0、相对预算0；+0与−0视为同值。** `real_T=double`见固定ZIP的`rtwtypes.h`；三个根输出均为`real_T`数组，见头文件356–358行。17位有效十进制日志保留原binary64，不把GPS缩放后的double擅自四舍五入成协议整数。

这个0来自本次“保留原生数值”的工程要求：原生double上任何可表示的非零变化都是值的变化，因此该要求不允许非零差异。它不是把机器epsilon、模型噪声幅值或SITL任务门槛冒充误差分析，也不声称ODE4截断误差或跨引擎舍入差为0。原规格不要求跨平台逐位一致；本合同选择更严格的短工况检验，数值相等也不等于文件/内存逐位相同。若失败，结论就是该严格判据未满足，不能据此直接推断模型物理失真，更不能事后放宽v1来取得通过。
