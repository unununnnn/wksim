# Vehicle60 时间字段的证据范围

本次形成一个待审阅的时间表达前提，未批准 G6 误差预算。对象是 rfw9nmbb 实际使用的生成模型，在运行时 step 返回后读取的 `Vehicle60[2]`。它不能直接替代同源 11.8 major 采样的时间规则；后者的版本和采样阶段绑定仍在核验。

必须区分理想有理数时间 `k/1000`、该有理数的正确舍入 binary64 值，以及实际的 binary64 乘法 `k * 0.001`。主会话独立使用标准库 Fraction 和 binary64 位序枚举 k=0…98684，未调用代理自写的舍入算法：

| 量 | 结果 |
| --- | --- |
| 乘法结果与正确舍入有理数相同 | 85,555 个 tick |
| 两者不同 | 13,130 个 tick |
| 最大可表示数间距计数 | 1 |
| 相对精确有理数的最大绝对误差 | 1/109951162777600 秒，约 9.09e-15 秒 |
| 误差除以乘法结果向正无穷方向的相邻间距 | 最大 17/25，约 0.68 |

最后两类误差与整数间距计数是不同指标。已有留存验证另外检查了每个载具 98,684 条实际运行记录，时间值均与乘法形式逐位相同；该观察不意味着它等于精确实数时间。

现有 wrapper 只检查与乘法形式之差是否不超过 1e-8 秒。增加 5e-9 秒的反例仍可通过这个保护条件，却不再满足逐位相等，因此保护条件不是精确相等的证明，也不是本次新增的容差。

公开材料位于 `validation/coordination/g6-time-premise-acceptance-20260913-01/`，包含独立枚举脚本、结果以及带来源哈希的精简前提。没有包含厂商代码正文。原始错误草稿、修正记录和完整留存验证继续保存在本机；R1、G6 和 Full 状态未改判。
