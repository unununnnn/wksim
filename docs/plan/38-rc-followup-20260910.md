# RC candidate integration follow-up — 2026-09-10

Work continues from a875a13 / 762eda3. No hardware is involved.

Preflight source inspection found that the previous task/publisher used the wrong
source literal, physical position indices, and that Humble's executor drops message
metadata and calls callbacks with one argument. Its native take_message metadata
exposes only source_timestamp and received_timestamp. A nominal two-argument
on_rc callback therefore cannot provide publisher-GID ownership on this runtime.

The new installed control candidate includes a small rcl_take_serialized_message
adapter. It takes from a subscription on an unspun, owned node while holding the
Python subscription handle. It returns actual serialized bytes and the RMW
publisher_gid; no discovery-derived per-packet identity is substituted. It does
not modify /opt/ros or the native flight controller adapters. The library is
built with rcl/rmw headers from the installed Humble and separately sealed in the
candidate manifest. Real DDS tests distinguish two writers and match their actual
packet GIDs against discovery endpoints.

Reference: https://github.com/ros2/rclpy/blob/humble/rclpy/src/rclpy/subscription.cpp
(public pointer property and the original take_message implementation).

Additional fixes preserve the frozen 38-rc-contract.md semantics:
- receive/produced freshness uses CLOCK_MONOTONIC; integration uses operation time;
- duplicate/foreign stream or epoch messages do not refresh ownership;
- reset retires the previous stream;
- RC setup requires airborne external-mode feedback and one bound writer;
- COMMAND -> RC clears old task references; RC -> COMMAND requires neutral intent,
  captures the current actual pose, and requires a fresh explicit request;
- command intent alone holds, while release/expiry/mode loss withdraw control;
- task first uses normal COMMAND takeoff and only then explicitly enters RC.

18 RC tests passed under Humble: pure input, real generated-message node methods,
and actual two-writer DDS CDR/GID receive. The sealed legacy resource check now
compares historical CMake/package inputs against the historical staged tree;
current candidate inputs remain separately checked against its stage/install.
Nine admission tests pass under WSL, including historical-input tampering. The
Windows run of the existing symlink-escape test failed for lack of symlink rights;
that test was executed successfully in WSL instead.
