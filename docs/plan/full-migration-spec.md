# wksim 完整移植规格（已批准）

2026-09-05。由当前会话与[Wayfinder：Prometheus 双飞控 SITL 移植（UE5.5 / ROS2 / DDS）](https://github.com/unununnnn/wksim/issues/1)综合生成。用户以“确认开始”批准测试接缝、38张实施票据及阻塞拆分；本规格不代替既有决策票。

## Problem Statement

用户需要把Prometheus迁移为可持续开发、可独立构建的wksim仿真工具链：保留任务、控制和实验来源，支持PX4及ArduCopter，以UE5.5显示载具和场景，以WSL Ubuntu22.04、ROS2与DDS组织运行。现有单机闭环与显示验证已经证明部分边界可行，但还不是统一可操作的产品，也没有覆盖已冻结的CopterSim公开完整版全部功能。

本机保留RflySim工具、SDK、模板、生成模型和预览资料，却没有当前完整应用源码。项目不能把启动原版程序当作自主实现，也不能以Gazebo作为最终必需后端。多个独立实验同时运行不等于联合场景；报文存在、命令受理、飞控ACK与动作完成必须分别验证。

## Solution

建立以Prometheus为主体的wksim工具链。WSL承担自主仿真核心、原生双飞控DDS适配、任务和ROS2编排；Windows承担UE5.5异步显示及可选模型DLL宿主。工具链提供模型/场景/飞控配置、启动停止、任务执行、实时状态、记录回看、故障与兼容性验证的完整操作路径。

优先交付一个可复现的双飞控SITL产品闭环，再沿冻结的公开完整版逐项扩展模型、工具、通信模式、其他仿真模式和实验。核心在没有原版CopterSim程序、闭源DLL、Gazebo或MATLAB运行时参与的情况下仍须独立构建运行；可选DLL导入能力仍在完整终态内。保留原功能与操作流程，采用wksim界面，不复制品牌或像素布局。

## User Stories

1. 作为迁移维护者，我希望每个迁移行为都能追溯到固定Prometheus基线，以便确认主体未被其他项目替换。
2. 作为使用者，我希望从一份实验配置选择PX4或ArduCopter，以便不必重写任务逻辑。
3. 作为使用者，我希望先看到环境、版本和端口检查结果，以便在飞行开始前发现不可运行的配置。
4. 作为使用者，我希望启动后明确看到模型、飞控、Agent、定位和任务接管各自的状态，以便知道系统正在等待什么。
5. 作为使用者，我希望通过同一Prometheus入口正常解锁、起飞、悬停、飞航点和降落，以便比较两套飞控的实际行为。
6. 作为使用者，我希望未支持的模式在命令受理前明确拒绝，以便不会悄悄执行另一种动作。
7. 作为使用者，我希望分别看到命令受理、飞控确认和动作完成，以便不会把发送成功误认为飞行成功。
8. 作为使用者，我希望重复、过期、旧运行代次和错误载具的命令被拒绝，以便重连后不会重放旧运动。
9. 作为使用者，我希望暂停、步进、继续和倍速具有明确时间语义，以便实验可复现且不由显示帧率决定。
10. 作为多机实验者，我希望同一联合场景的全部载具共享一条权威仿真时间线，以便相互作用发生在一致时间上。
11. 作为多机实验者，我希望独立实验明确标识不同环境与时间线，以便不会被误报为联合场景。
12. 作为多机实验者，我希望命名空间、身份、端口和输出目录互不冲突，以便同时运行多个实例。
13. 作为使用者，我希望故意断开DDS时得到可验证的失联行为，以便知道飞控和任务层各自如何处理异常。
14. 作为使用者，我希望外部切换飞行模式或状态重置后任务层不自动抢回控制，以便控制权边界明确。
15. 作为使用者，我希望停止一次实验只收尾该实验创建的进程，以便不会影响已有飞控或其他用户工作。
16. 作为使用者，我希望UE5.5显示真实载具位置、姿态与旋翼，以便画面与物理状态一致。
17. 作为使用者，我希望视景断流时显示陈旧提示，恢复时显示当前状态，以便不会误读旧画面。
18. 作为使用者，我希望关闭UE也不停止物理或飞控保活，以便能执行无界面的实验。
19. 作为场景作者，我希望载具、场景、坐标、单位与原点绑定清晰，以便导入资产后不发生比例或位置错位。
20. 作为场景作者，我希望地形和碰撞反馈带有明确有效时间，以便物理环境耦合不被异步显示破坏。
21. 作为感知开发者，我希望视觉传感器数据关联真实位姿、时间和标定，以便使用Prometheus感知与规划实验。
22. 作为使用者，我希望在wksim界面完成配置、启动、任务执行和结果查看，以便复现原工具的完整操作流程。
23. 作为批量实验者，我希望同一配置能够从CLI或NoUI运行，以便自动化不依赖人工点击界面。
24. 作为模型开发者，我希望加载一个有明确构建来源的模型并验证输入输出，以便核心自主性可以被独立证明。
25. 作为模型开发者，我希望修改模型参数后可导出、重载并观察实际动力学变化，以便参数工具不是空表单。
26. 作为模型开发者，我希望按已冻结范围接入多旋翼及其他构型，以便首个四旋翼不会被误认为全部机型。
27. 作为模型开发者，我希望可选导入经过ABI验证的原版DLL，以便复用本地资源而不把DLL变成必需依赖。
28. 作为模型开发者，我希望模型初始化、重置、步进、终止和故障都有可观测结果，以便定位插件兼容性问题。
29. 作为模型开发者，我希望可选Windows DLL宿主崩溃时隔离失败，以便不破坏其他实验或原厂安装。
30. 作为模型开发者，我希望构建期可使用现有MATLAB/Simulink模板生成模型，以便复用工具而不要求日常仿真启动MATLAB。
31. 作为MATLAB用户，我希望使用基础tcpclient和JSON接入可选桥，以便不强制购买或依赖额外通信工具箱。
32. 作为MATLAB用户，我希望读取状态/日志及发送允许命令的具体范围被明确列出，以便接口不会被含糊的“支持MATLAB”替代。
33. 作为MATLAB用户，我希望断开连接不影响主仿真，以便接口保持可选；写入操作必须经过能力、时效和运行身份检查。
34. 作为地面站用户，我希望查看状态、参数和必要控制，并明确控制权转移，以便与任务节点协同而不争抢控制。
35. 作为SDK用户，我希望冻结范围内的报文、字段、操作和错误行为经过对照，以便现有脚本能有依据地迁移。
36. 作为实验者，我希望传感器、执行器和环境故障可按固定事件注入并记录，以便评估控制与恢复行为。
37. 作为实验者，我希望配置、模型、飞控、消息类型、工具和运行结果有版本与哈希记录，以便复现差异。
38. 作为实验者，我希望记录和回看能还原当时的状态、命令与异常，以便失败不会仅剩一张截图。
39. 作为验证者，我希望数值对照在运行前固定初态、输入、种子和误差阈值，以便不会事后放宽标准。
40. 作为验证者，我希望以物理真值和持续驻留验证动作完成，以便瞬间越过目标不被算作成功。
41. 作为验证者，我希望每个公开完整版功能都关联参考依据、实现和测试，以便无法观测或尚未实现的项目不会被隐藏。
42. 作为验证者，我希望不同通信和仿真模式逐项声明已验证范围，以便发现一个端口不被当作全协议兼容。
43. 作为后续HIL使用者，我希望硬件连接、安全操作和验收场景单独明确，以便软件代理不会在未经授权的硬件上执行测试。
44. 作为维护者，我希望优先复用已有环境、库、模板和工具，以便不重复安装大型套件或维护多余基础设施。
45. 作为维护者，我希望本地可用资源和可公开分发资源分别记录，以便不误发布许可不清的厂商源码或二进制。
46. 作为维护者，我希望Codebase Memory按实际源码变更更新并注明未覆盖范围，以便图索引不会替代源代码核对。
47. 作为项目负责人，我希望实施票据有真实阻塞关系和完成证据，以便多个代理可并行而不改同一边界。
48. 作为项目负责人，我希望阶段完成与项目完整完成有不同判据，以便创建规格、运行单个模型或通过单次演示不会提前结束Goal。

## Implementation Decisions

- **已确认主体与平台**：Prometheus固定上游基线为5dcd8cfa764d558f3e15dcb88aa7d49e32c54cce；Windows UE5.5，本机5.5.4；WSL Ubuntu22.04与ROS2/DDS；PX4和ArduCopter均为首期真实SITL目标。AeroTwinSim只提供复用参考。
- **已确认物理边界**：自主核心取代Gazebo，核心不依赖原版CopterSim程序或闭源DLL；不卸载已有环境。WSL负责外部物理SITL核心与双原生DDS，Windows负责视景及可选DLL宿主。SIH等后续模式须分别映射其物理权威，不能套用错误的外部物理假设。
- **已确认完整范围**：冻结2026-09-05公开Full文档范围，仿真模式标识0–11、通信模式标识0–6只是盘点锚点，不是完整功能总数。定制版Redis与厂商品牌定制服务不自动纳入；wksim自有界面仍必须实现。
- **已确认时间边界**：联合场景共享唯一权威仿真时间；UE异步消费状态，不成为物理节拍来源。独立实验不能冒充联合场景。不同飞控频率、掉队、重置和暂停行为的具体策略仍由既有时间决策票确定。
- **已有接口基础**：保留Prometheus消息语义和来源，ROS2命名变化有映射。复用已迁移命令处理、输出修整与原生适配，保持ENU/FLU和SI语义；飞控及UE坐标转换限于各自适配边界，高度基准必须明示。
- **已有双栈能力边界**：共同位置任务已经通过真实SITL。ArduCopter当前使用显式可选偏航与状态候选及匹配消息层，不能泛化成原版固件都支持；未支持模式继续拒绝，不静默降级或回退为另一种控制传输。
- **已有控制生命周期边界**：定位就绪、命令受理、原生ACK和任务接管分别建模；正常解锁检查保留。初始原生起飞的偏航对齐不等于活动任务任意重置都可忽略；离开外部模式不自动重获控制。
- **已确认MATLAB传输**：基础tcpclient加JSON，可选桥接ROS2，不要求ROS或Instrument Control Toolbox；MATLAB原生ROS2直连须另行联测。读取状态/日志、白名单配置与高层任务命令为范围候选，不冒充用户已确认的功能集合。
- **已批准的实施组织**：优先复用已有标准库、ROS2 launch、消息及验证器，按可独立演示的纵向切片推进；不新造统一万能中间件。生产运行入口与验证器共享配置和行为，观察器不得暗中代发控制。
- **待决策而非默认批准**：正式数值预算、首期最终验收矩阵、联合场景调度与掉队策略、插件ABI及环境反馈契约、MATLAB操作范围、后续硬件/性能规模。各实施票只依赖真正阻塞它的决策；一个未定接口不应阻塞无关已确认工作。
- **资源与发布边界**：可以在本机范围复用和兼容性分析，但不修改原厂安装、不绕过许可、不发布未确认授权资源。源代码提交/远程推送另按用户授权办理，不把混合工作区整体推送。
- **领域约束**：AeroTwinSim的Gazebo物理权威、NED公共边界、特定机型规模及控制屏障ADR不自动继承到wksim；与本项目冲突时服从本项目已确认决议，不静默套用。

## Testing Decisions

以下最高层验收接缝已获用户确认，作为实施票据的共同准入条件。

1. **主黑盒接缝：一次实验的用户操作路径。** 配置运行→环境预检→启动→同一Prometheus任务入口→两套真实飞控分别或联合执行→UE观察真实状态→停止→读取机器可检验的证据包。CLI与界面只是同一操作行为的不同入口，不分别维护两套飞行逻辑。
2. **必要跨边界接缝。** 固定消息/坐标/时间/身份契约、模型插件输入输出与MATLAB TCP/JSON是确实跨系统的边界。对它们增加精确边界测试，不给每个内部类制造新的测试接口。
3. **真实闭环标准。** 主验收使用真实PX4、ArduCopter、自主物理与安装后的产品节点；同时保存独立真值。禁止观察脚本代发原生命令，禁止mock飞控、预置轨迹或原版程序替代产品成功。
4. **既有测试先例。** 保留47个接口、52个生成类型、104次CDR检查及现有51项自动检查；保留命令102组、输出修整332组原C++对照及候选偏航接入层111条断言的适用范围。计数是当前基线，不是未来用测试数量衡量完整度的目标。
5. **已通过的控制集成门槛。** 起飞至少2.5m；5飞控秒保持窗口高度误差不超过0.6m、倾角不超过0.35rad；航点误差不超过0.5m且速度不超过0.5m/s并驻留2飞控秒；降落高度绝对值不超过0.3m且解除解锁。真值另作检查。这些门槛不得当作动力学等价预算。
6. **时间和恢复。** 联合场景核验单一时钟、运行代次和步编号的一致性；暂停/单步/倍速、迟到输入和重置应有预先声明的预期。墙钟安全超时不因ROS时钟暂停而消失；重连不得重放旧运动。
7. **异常和隔离。** 地面重连已有证据，空中DDS失联、模式外切、飞控退出、插件崩溃、显示断流和输出阻塞须分别测试。每次仅操作本次创建的进程，硬件测试另行授权。
8. **模型与数值。** 固定来源、模型、初态、输入、种子和参数，比较完整约定量和误差包络。正式阈值必须在运行前锁定；既有同构建重复性、有限数值检查不能代替物理精度验收。
9. **资源与产品。** 在没有原版应用、闭源DLL、Gazebo及MATLAB运行时的配置下证明核心仍可构建运行；可选扩展单独启用、禁用并测试失败路径。UI人工可视检查必须伴随状态/坐标证据，截图不能独自证明动作完成。
10. **证据资格。** 每票记录命令、配置、版本/哈希、预期、实际、日志和残留进程检查；保留失败案例。没有实际执行的构建、协议、场景或硬件不能记为通过。最终覆盖矩阵中未知、阻塞和未实现必须可见。

## Out of Scope

- 此规格不要求恢复当前厂商完整应用源码、复制品牌、像素级原界面或跨平台浮点逐位相同。
- 不以UE5.6升级、Gazebo回退、替换Prometheus主体或重装现有大型环境作为实施捷径。
- 不修改厂商安装、绕过许可、发布权限不明资源或未经授权向真实硬件发送命令。
- 首期SITL验收不包含真机/HIL通过承诺，但Full范围内相关模式仍是后续项目义务，不能从终态删除。
- 定制版专属扩展另行立项。未取得公开定义或可观测依据的能力不得靠猜测宣称等价。
