## 已取得的决策证据

沿用最终 AP/Control 候选和两个真实飞控，由两个安装的 Prometheus 控制节点正常解锁并起飞。在共同 tick 51504 暂停 4 个墙钟秒时，AP/PX4 真实高度为 2.960/2.811m；模型、ROS 权威时间和传感器步数保持不变，暂停与停止共增加 0 个物理步。

原始 DDS 显示 AP/PX4 在暂停后约 1.538/1.994 秒以 `native_state_stale` 撤销控制；两个公共任务失败。两种原生位置输出在撤销前仍持续了一段时间。这说明已有独立飞行的墙钟新鲜度不能直接表达“已授权冻结”。它不是放宽真实通信失联检查的理由。

证据为 `validation/joint-public-flight-_e9clfj2/pause-audit.json`。这是限定诊断；任务没有完成降落，不算联合暂停/恢复验收。

## 推荐的下一纵向切片

沿用正式实验配置和公共任务输入，在已接管的共同位置保持阶段完成：请求暂停 → 双控制节点确认暂停边界 → 冻结共同物理/ROS 时间 → 单次四 tick → 再暂停 → 用户显式继续 → 完成原任务及正常降落 → 停止与离线证据回看。首条路径的阶段限制必须明确拒绝，不能把未实现的起飞/降落中暂停静默当作成功；这些 Full 义务继续留账。

### P1：用户暂停期间的任务语义

推荐保留当前有效目标、任务身份和未完成驻留时间。任务驻留与操作完成期限不消耗暂停的墙钟时间；不发送新的高层模式、解锁、起飞或航点请求。经过显式“继续”后，使用新原生样本确认状态，再继续同一已授权任务。已撤销控制、代次变化、状态失效的任务不能沿此路径恢复。

暂停状态不能只由 `/clock` 不变化推断。须有同一场景 epoch、严格递增生命周期请求身份、最后完整屏障及双控制节点确认。暂停状态可显示“冻结的有效快照”，不得把它标为仍在更新的飞行状态。

### P2：保活和独立监督

推荐仅在有时限的场景暂停许可持续有效时，区分“源仿真时间按约定冻结”和“真实链路异常”。控制节点继续发送当前有效目标所需的原生保活；不回放历史目标队列，不伪造新状态时间戳，不填充虚假 RC，不放开 FC 健康检查。

保留独立墙钟监督：场景所有者、模型/飞控/Agent/控制进程身份、物理通道、DDS 端点和许可时效。缺许可、身份改变、通道关闭或进程退出时，任务控制撤销且全场景冻结。暂停许可不能让坏状态重新变有效；仅凭进程存活也不能把 DDS 可用性判通过。真实失联验证必须作为同一接缝的负向案例。

### P3：明确的异常及恢复限制

推荐在迟到、掉队、DDS/物理链路异常后保持冻结并撤销任务控制。链路恢复不自动恢复物理或任务。用户的“恢复物理”只重新建立当前屏障，任务接管须另发新请求；不自动恢复已撤销任务。

模型仅部分完成一步、RPC 超时后状态不确定、epoch/原生时间倒退、模型状态不一致：只允许停止或 cold reset；不以回滚计数器伪装恢复。冷重置完整退场并生成新 epoch，清除所有旧任务/确认归属。

### P4：供确认的首期墙钟数值

这些是**待批准的监督候选值**，不是此前已批准值或 G6 数值预算：

| 项目 | 推荐首期值 | 超出后的行为 |
|---|---:|---|
| 场景生命周期许可发布 | 每 100ms | 独立于模型步和显示 |
| 许可有效期 | 500ms | 撤销任务控制、冻结场景，不能自动恢复 |
| 正常运行中的原生状态新鲜度 | 保留现有 2s | 真实失联处理，不通过暂停许可掩盖 |
| 单个模型 RPC | 3s | 整场景故障，须停止/冷重置 |
| 飞控输入屏障等待 | 5s | 冻结且锁存异常，迟到包不能自动推进 |
| 显式恢复的就绪等待 | 5s | 保持冻结并报告未就绪，不强行接管 |

这些值一旦获批须在运行前写入实验配置和证据；测试失败不能事后放宽。尚未证明 500ms 许可和 5s 恢复窗在本机各种负载下满足可用性；若不满足应报告并另提修订。
