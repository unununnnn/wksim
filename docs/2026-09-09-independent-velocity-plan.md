# #32 独立入口验证的预先约定

2026-09-09，#32原票只要求同一公共Prometheus命令的双栈速度/回中/偏航工况，未要求同一联合场景。保留此前所有联合rate_unmet失败及联合倍率义务，本轮使用正式independent_quad_dds_v1分别验证同一已准入Control/固件。独立成功不证明联合倍率达标，也不覆盖#20。

在首次独立实跑前冻结：使用现有Task.execute_velocity_yaw，命令(0.8,0.4,0)m/s ENU、零速、yaw-rate0.5rad/s及AP错误组合拒绝不变。速度逐轴误差0.3m/s≥3s、零速0.25m/s且漂移1m≥4s、偏航积分误差0.35rad≥4s、拒绝后速度0.25m/s≥2s；位置基线沿现有0.5m/0.5m/s/0.15rad。独立采样约50Hz，驻留预先增加固定0.5s观测余量，审计仍要求完整原物理最小时间，不从测得差异选容差。

PX4扩展run02保留failed：惯性/偏航速率和速度+yaw角跟踪通过，但角度模式回中在固定2.5s后仍有0.265m/s观测速率，未满足0.25m/s。新一轮之前将这个额外工况的准备段改为最多10墙钟秒等待达到原速度/漂移/角度条件，再连续满足1.5s才开始原4s最低保持验收（实际安排4.5s）。不改飞控、位置保持控制律、任何误差界或失败数据；未达到条件会有界失败，不能只挑已通过的跟踪段。

run03第一次进入条件后又离开，因此准备段没有成立，整轮仍failed。下一次运行前将准备段落实为连续稳定计时：条件失效只清零准备计时，在最多12墙钟秒内必须连续满足原条件1.5个FC boot秒；正式4.5s保持段仍遇任何违例立即失败。该修改只区分收敛准备与已声明保持，不隐藏正式窗口内的异常。

每场先以真实公共命令完成[2,3,3] ENU位置基线及2.5s驻留，再执行原速度profile并落地；这个位置基线也满足正式独立runtime现有单航点物理门，不关闭或替换该检查。额外基线使用command_id1，后续原profile command_id整体+1，公共request_id仍由现有Session生成，错误组合也采用相同偏移。入口明确包含位置基线，没有把它隐藏在读取/预检操作中。

首次PX4惯性速度探针完整通过后，在新增工况运行前补充冻结覆盖：双栈增加XYZ_VEL_BODY的(.8,.4,0)速度与零速保持，按每个样本当前偏航转回body_flu，仍使用逐轴0.3m/s≥3s、速度0.25m/s/漂移1m≥4s。PX4另做非零惯性速度+yaw角0.6rad，速度门槛同前，角度门槛沿已有位置任务0.15rad≥3s；AP仍拒绝该组合。驻留仍加固定0.5s采样余量，未扩大误差。完整场景command_id为位置基线1、惯性速度/零/偏航2–4、PX4角度速度/零或AP重保持/拒绝5–6、机体速度/零7–8、LAND9。首次惯性探针及源码另留存，不把未测body/角度当作通过。

发现并以实际Task方法的无I/O测试复现：非共享时钟下dwell使用FC boot时间，但旧偏航期望使用墙钟，3×时会误报。修正为与dwell相同的时钟选择（联合ROS时间/独立FC boot时间），不改墙钟超时和所有误差数值。clock-red.log保留旧代码失败，clock-green.log确认独立3×和共享ROS两路径通过。

每个阶段记录真实公开状态、native_boot_s、观察Unix/monotonic和实际物理日志游标。独立物理时间不冒充联合1ms网格，不把PX4独立uav1重新标成联合uav2；后续原始审计按真实50Hz时间/游标计算速度与偏航积分。当前仅实现候选入口，真实试飞/原始审计未完成前不关闭#32。
