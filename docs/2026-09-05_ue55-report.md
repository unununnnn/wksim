# 双飞控 UE5.5 实时显示与断流验证

2026-09-05，本机分别完成了 ArduCopter、PX4 原生 DDS 飞行与 UE5.5.4 实时显示。两次测试均执行正常解锁、起飞、保持、航点、降落上锁，并在空中暂停显示数据约3个墙钟秒；物理模型继续推进约9个仿真秒，画面显示 STALE，恢复后显示最新状态。21项自动化检查通过，实际引擎截图已经逐张检查关键帧。**这是自主物理/DDS/UE运行边界的本机验证，不是完整 CopterSim、Prometheus业务迁移、图像传感器或数值等价验收。**

## 实现与预先声明门槛

新增 [UE工程与协议说明](../Simulator/ue55/README.md)、只读最新状态桥、[Windows启动器](../tools/validate-ue55.ps1)和[验证器](../tools/validate_ue55.py)。原参考viewer固定六旋翼，因此没有给它改名来冒充四旋翼；新模块以四旋翼几何体验证接口，保留参考城市资源。内容插件只补齐两个材质/纹理资源，不包含原飞行运行模块。

跨系统路径为“WSL独立模型写真值 → Windows只读尾读/合并最新状态 → 回环UDP → UE Actor”。飞控指令和状态仍通过WSL原生DDS。此共享文件桥是私有网络命名空间下的本机诊断手段；不是最终ROS2模块分发或性能结论。

| 检查 | 门槛 | 不代表什么 |
| --- | --- | --- |
| 位置回读 | Actor与源NED→UE变换的欧氏误差≤0.0002cm | 不是厂商动力学精度 |
| 姿态回读 | 归一化四元数、符号等价后的L2差≤0.000002 | 不是相机标定或像素投影验收 |
| 源时间 | 回读误差≤10^-8s，帧号和源时间严格递增 | 不是多个模型已共享同一世界时钟 |
| 断流 | 物理高度达到2.5m后暂停发送3墙钟秒，源时间至少前进1s | 不是飞控DDS空中失联矩阵 |
| 显示证据 | ≥30个实际Actor回读；空中LIVE、断流期间STALE、恢复后LIVE截图 | 不是帧率/吞吐/视觉质量终验 |
| 输入拒绝 | 9个错误标识、次序、版本、数组/数值用例全部拒绝 | 不是完整安全协议或模糊测试 |

每次测试开始前写入 `thresholds.json`。物理和DDS沿用此前固定工况与门槛：3m目标、保持5仿真秒、NED `[3,2,-3]` 航点及2秒驻留、降落上锁，具体参数见原生DDS报告。动力学/传感器对照仍按用户确认的固定模型、输入、初态、随机种子和时间条件另行制定误差预算。

### 首次失败与修正依据

- `validation/ue55-arducopter-40806d78` 保留失败：位置阈值初设10^-5cm，实测微移回读差2.68724×10^-5cm。UE5.5本地 `SceneComponent.cpp:2994` 使用 `NewLocation.Equals` 抑制微小更新，`Vector.h:370` 默认容差为 `UE_KINDA_SMALL_NUMBER`，`UnrealMathUtility.h:130` 定义为10^-4。修订门槛按三轴范数上界取0.0002cm；姿态按三轴10^-4度容差取2×10^-6四元数L2。没有修改引擎或物理精度去迎合测试。
- 参考地图缺少 `/AeroTwinVisualRuntime/.../MI_RefHexX_Body`，使用回退材质；实时SkyLight缺天空，Lumen缺距离场。补齐内容依赖、SkyAtmosphere和距离场，不关闭渲染警告来伪装完成。
- 参考生成源码 `AeroTwinBootstrapAssetsCommandlet.cpp` 中停机坪最高面为34cm；原机体在地面被遮挡。显示场景下移34cm，物理真值和Actor不加偏移。建筑仍是视景装饰，不冒充物理地形/碰撞。
- `validation/ue55-px4-d6c772c9` 保留失败：PX4真值没有AP的 `frame` 字段。桥现为PX4使用完整JSONL记录序号，保留原始模型时间；新增无frame和半行/积压回归用例。
- 中途 `ue55-build-b12300f1` 因SkyAtmosphere头文件路径错误编译失败；按本机5.5的 `Components/SkyAtmosphereComponent.h` 修正后编译通过。其日志未覆盖。
