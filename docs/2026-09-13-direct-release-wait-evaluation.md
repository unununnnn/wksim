# 直接 CPython 等待候选评估

直接 CPython 扩展已编译，31 项真实接口检查通过；它比 ctypes 接法开销小，但本轮没有展示优于 Python 轮询的总返回延迟，因此不接入生产节拍器。原 1ms、4tick、100ms、无追赶及已通过的飞行证据保持。

扩展使用 METH_O 直接 C callable，等待期间保持 GIL，在 C 内拒绝布尔值、非精确 int、负数和 int64 溢出。加载器校验文件 SHA、平台与版本，直接返回 C callable。主审补全模块结构初始化，并修正 `3.100` 被误认成 `3.10` 的版本判断。两加载器合计 24 项纯测试通过；真实接口另验证 31 项参数和时钟行为。

## 实测

每轮四种方式轮转，各 30 次热身、1000 次样本；主指标为返回 Python 后即刻读钟减 deadline。内部 C 时间戳另列，不拿它代替返回成本。

| 环境 | 模式 | 返回中位数 | 1000次累计返回延迟 |
| --- | --- | ---: | ---: |
| 默认可用20 vCPU | Python | 145 ns | 2.435002 ms |
| 默认可用20 vCPU | CDLL | 2340.5 ns | 6.212127 ms |
| 默认可用20 vCPU | PyDLL | 1649.5 ns | 4.915959 ms |
| 默认可用20 vCPU | 直接扩展 | 531.5 ns | 3.398046 ms |
| 仅自有基准线程固定vCPU0 | Python | 158 ns | 3.776265 ms |
| 仅自有基准线程固定vCPU0 | CDLL | 2431.5 ns | 6.321524 ms |
| 仅自有基准线程固定vCPU0 | PyDLL | 1638.5 ns | 4.320323 ms |
| 仅自有基准线程固定vCPU0 | 直接扩展 | 530 ns | 3.949961 ms |

第二轮只改变自有基准线程的亲和性，进程退出即结束该设置，没有改变系统或用户进程。两轮处在不同 WSL boot，不能将跨轮差异归因于固定 CPU；它们也不包含实际飞控、健康检查、模型 RPC 和完整倍率窗口。总计 8000 条原始记录已独立重算分布并核验时间顺序。没有依据这些微基准宣布 RateUnmet 已修复。
