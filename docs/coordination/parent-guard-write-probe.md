# 父进程监督与同步写入探针

第六场 `aruco-track-692e75fb3b` / `0bc5d47a339a4773bf26dc5f9b853ac5` 在 tick6312、累计迟到102.642592ms触发原倍率保护；未启用RGB，已清理。减少重复raw轮询尚不能称为性能问题已解决。

任务工作进程由联合监督器直接创建。新守护在启动时核实内核父PID、实际pid/pgid/start_ticks并二次检查父PID，之后每次health直接读取内核父PID。原父退出后内核重新托管该子进程，复用的PID不会变回其父进程，因此无需每轮重新解析两个/proc文件。真实父退出测试通过；检查频率、控制许可和失败语义不变，仅限Linux。

新增 `--write-timing` 只启用监督器的同步日志写入观察，记录wire/rate/clock/public-dds/lifecycle各实际write调用的墙钟、线程CPU、逻辑字符计数与底层文件偏移。仅慢于1ms或失败的调用逐条落盘，所有调用计数和最大值写入结果。它不改变原始日志内容、不额外flush、不异步化写入，也不覆盖模型工作进程、Task raw日志或Windows图像写入，不能直接把耗时归因为磁盘。

探针默认关闭；`write-timing.jsonl`与运行一起归档。字节保留、异常传递及不刷新缓冲区的4项检查通过，相关WSL检查共48项（3项条件跳过）。下一场在原门槛下使用该探针检验日志写入是否解释已有尖峰；未验证前不更改日志架构或倍率合同。
