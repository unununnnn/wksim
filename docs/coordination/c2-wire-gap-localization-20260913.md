前两个大组的显著间隔位于传感器记录与执行器输入记录之间；第三个大组不能用该间隔解释大部分工作耗时。因此诊断仍需区分 native 输入路径与其他 manager 工作，不能笼统归因于同一飞控或日志。

这些数值是同一流水中序列化的浮点墙钟秒差，按最近整数纳秒列出。区间包含日志编码、健康检查、等待及可能的调度延迟，不是纯网络延迟或 CPU 时长；AP/PX4 区间可能重叠，不能相加宣称闭合。无 CPU 探针的本场不能据此区分“进程在运行”与“进程在等待”。

脚本另以当前 Python 的 TextIOWrapper/BufferedWriter(65536) 模拟标准完整写入、无额外 flush 情况。该模拟不是实际系统调用跟踪，也不能排除其他日志或 I/O 开销。原始失败、1ms/native 屏障与全部倍率门保持；本次没有启动新 native 场。
