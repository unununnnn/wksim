# Candidate attitude entry contract, 2026-09-09

This is an explicit future-trial revision following the preserved first-flight failures. The executable candidate contract is `Simulator/wksim_runtime/attitude-entry-v1.json`; the task records its exact SHA256 and the unchanged original budget SHA256 `9a13e03abb5c9caf56d75ca4c5e4fd73d709037add7ec527405eee4d471d318f` before flight. Existing failed evidence remains failed.

PX4 preconditioning sends public XYZ_ATT with zero roll/pitch, entry yaw and the already frozen hover collective. It runs before the full two-second level calibration, before the first 5-degree step after position recovery, and before the full 0.2-second thrust baseline. No 5-degree or increased-thrust command precedes the applicable gate. The gate has a two-second physical and ten-second wall deadline starting before the neutral request, with the original physical abort envelope active even during acknowledgement waits.

The gate requires a new actual VehicleControlMode observation whose native timestamp is at least the neutral native input timestamp. Armed, offboard, attitude, rates and allocation must be true. Position, velocity, altitude, climb rate, acceleration, multicopter position, manual, auto and termination must be false. It then requires actual MAVLink ATTITUDE_TARGET neutral quaternion and frozen thrust, with native time_boot_ms strictly after that control-mode timestamp in common units. Message matching tolerance 1e-5 covers float32 transmission only; it does not loosen physical acceptance. Receiver freshness limits are 0.75 seconds for mode and 0.25 seconds for target.

The actual versioned/namespaced VehicleControlMode output is already configured at maximum 50 Hz in the fixed PX4 source export. This cannot accelerate Commander's approximately 500 ms update cadence. The unspun ROS Humble raw observer retains CDR, middleware timestamps, decoded native control flags and native timestamps, allowing actual publication cadence to be measured without requiring 50 Hz heartbeats. Publisher discovery records node, namespace and endpoint GID; the gate requires one nonzero endpoint and rejects identity changes. Humble's raw take metadata does not provide per-packet publisher GID, so discovery is not described as packet-level attribution. MAVLink records preserve received datagrams and identity-checked native peer/system/component. These are controller observations, not physical-success evidence.

For ArduCopter, the actual first-flight BIN readback was PSC_ANGLE_MAX=0 and ATC_ANGLE_MAX=30. The candidate uses a scoped PSC_ANGLE_MAX=10-degree recovery-command limit, retains ATC_ANGLE_MAX=30, and requires both readbacks before flight. The task only reads parameters; the runner owns the isolated candidate parameter file. The relevant native source is AC_PosControl.cpp: the parameter defaults to zero (125), get_lean_angle_max_rad chooses a positive PSC value ahead of ATC (1163), and NE_update_controller limits the target acceleration (763). This corrects recovery command magnitude, not the original 15-degree physical abort envelope. AP does not use the PX4 neutral mode gate.

The hover median, original physical limits, original durations, eight-second recovery and existing failed records remain unchanged. The new 5-degree command defines its original command-observation t0 only after preconditioning succeeds; no historic t0 is shifted or relabeled. Candidate completion still requires separate raw audit and does not establish production admission.
